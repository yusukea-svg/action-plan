# 行動計画表

複数の顧客案件について「最終目標 → 月別目標 → 週次行動」を記録・管理するブラウザアプリです。

- サーバー・ログイン不要。データは**各自のブラウザ(localStorage)にだけ**保存されます
- 外部へのデータ送信は一切しません
- チームでの共有は **Excel ファイルの書き出し/読み込み** で行います
- PC・スマホのどちらのブラウザでも使えます

---

## 1. 使い方

### 画面

| 画面 | できること |
| --- | --- |
| **案件一覧** | 案件名・ステータス・最終目標の期限・今週の行動数(完了/全体)を一覧表示。案件名/メモで検索、ステータスで絞り込み。<br>・「+ 案件を追加」:案件名の欄は入力すると次の欄が増え、複数の案件をまとめて追加できる(× で入力行を消せる)<br>・各行の × :確認のうえ案件を削除 |
| **案件詳細** | タブで切り替え。<br>・基本情報・関係者:案件名・ステータス・メモの編集、関係者(氏名・役職・連絡先・メモ)の追加/編集/削除、案件の削除<br>・目標:最終目標(内容・期限)と月別目標(年月・内容・達成度%)<br>・週次行動:週ごとの行動(内容・誰に・状態・期限日・メモ)。「誰に」はその案件の関係者が候補に出る(自由入力も可)。先週〜未来の週を表示し、それ以前は「それ以前の週を表示」で開く |
| **週次行動** | 全案件の行動を「1週」「4週」で切り替えて表示(週は月曜始まり)。<br>・1週:案件別に表示。状態ボタン(未着手/進行中/完了)をタップするだけで更新<br>・4週:行=案件、列=週の一覧表で、表示した週から4週分を全案件まとめて確認。状態はタップするたびに 未着手→進行中→完了 と切り替わり、各マスの「+ 追加」からその案件・その週に行動を追加できる(スマホでは案件ごとのカード表示)<br>・先週以前の未完了は「持ち越し」として上部に表示。前週/次週へも移動可<br>・選んだ表示期間はブラウザに記憶されます |
| **まとめて入力** | 「週次行動」画面または案件詳細の「週次行動」タブの「まとめて入力」から開く。案件(複数選択可。「進行中をすべて選択」あり)・開始週・週数(2/4/6/8週)を選ぶと、案件ごとに週別の入力欄が並び、複数案件・複数週の行動(内容・誰に・期限日)を一度に登録できる。入力すると次の入力欄が自動で増える。登録後も画面に残る |
| **データ管理** | Excel 書き出し、JSON バックアップ、Excel/JSON 読み込み、最終バックアップ日の確認 |

- **期限が近いもの**:全画面の上部に、期限まで3日以内の週次行動(期限日を設定したもの・未完了)と最終目標(完了済み案件を除く)を表示します。期限を過ぎて未完了のものも「◯日超過」として表示します。行動は「完了」ボタンでその場で完了にでき、項目をタップするとその案件を開きます。「閉じる」で1行に折りたためます(状態はブラウザに記憶)
- 一覧の行・リストの項目をタップすると編集画面が開きます
- 削除するときは必ず確認ダイアログが出ます(案件を削除すると、その案件の関係者・目標・行動もすべて削除されます)

### チームでの受け渡し(Excel)

1. 渡す側:**データ管理 → Excelに書き出し**。`行動計画表_YYYYMMDD.xlsx` が保存されます
2. 受け取る側:**データ管理 → 読み込み** でファイルを選ぶ
3. 取り込み方を選ぶ
   - **既存データに統合**(通常はこちら):同じIDのデータは「更新日時が新しい方」を採用。手元にしか無いデータは残ります
   - **全置換**:手元のデータをすべて消して、ファイルの内容に置き換えます
4. 件数のプレビュー(新規・上書き・手元を維持・読み込み後の件数)を確認して「読み込む」→ 確認ダイアログで実行

#### Excel の構成

| シート | 内容 | 読み込み |
| --- | --- | --- |
| 案件 / 関係者 / 最終目標 / 月別目標 / 週次行動 | 1行1レコード。各行に ID・案件ID・案件名・更新日時を持つ | 対象 |
| 案件別サマリー | 案件ごとの目標・行動をまとめた閲覧用シート | 対象外 |
| 情報 | 形式バージョン・書き出し日時 | バージョン確認に使用 |

#### 注意点

- **ID・案件ID・更新日時の列は消さないでください。** 統合時の突き合わせに使います
- Excel 上で内容を直接修正した場合、更新日時も新しくしないと「統合」では手元のデータが優先されます(確実に反映したい場合は「全置換」を使います)
- Excel で行を追加する場合、ID は空欄で構いません(読み込み時に自動で振られます)。案件IDが空でも案件名が「案件」シートと一致すれば紐づけます
- 以前の版で書き出した Excel(見出しが「会社名」、「誰に」列なし)もそのまま読み込めます。ただし新しい版で書き出した Excel は古い版のアプリでは読み込めないので、チーム全員が同じ公開URL(最新版)を使ってください
- 「統合」では**削除は伝わりません**(相手が消したデータも手元に残ります)。削除を反映したい場合は「全置換」を使ってください

## 2. バックアップ運用

データはそのブラウザの中にしかありません。次の場合に**消えてしまう**ので、定期的に書き出してください。

- ブラウザの「閲覧履歴データ(Cookie とサイトデータ)」を削除したとき
- シークレット/プライベートウィンドウで使ったとき(閉じると消えます)
- 別の端末・別のブラウザに切り替えたとき(データは引き継がれません)
- iPhone の Safari で長期間(7日以上)サイトを開かなかったとき(Safari の仕様で消える場合があります)

おすすめの運用:

- **週に1回(例:金曜の夕方)Excel に書き出し**、共有フォルダ等に保存する
- 書き出した日時は「データ管理」に「最終バックアップ」として表示されます
- 最後のバックアップから **7日以上経ち、かつその後に変更がある**場合、画面上部に書き出しを促す表示が出ます
- 端末を移行するときは、旧端末で書き出し → 新端末で「全置換」で読み込み
- JSON バックアップはアプリ内部形式そのままの完全バックアップです(Excel と同じく読み込めます)

## 3. 開発

必要なもの:Node.js 20 以上

```bash
npm install
npm run dev       # 開発サーバー(http://localhost:5173)
npm test          # 単体テスト(データ操作・統合・Excel往復)
npm run build     # 本番ビルド(dist/ に出力)
npm run preview   # ビルド結果の確認
```

### 構成

React + Vite + TypeScript。画面が4つあり、タブ・ダイアログ・一覧の状態が多いため、型付きのコンポーネントで分割した方が素の HTML/JS より保守しやすいと判断しました。外部ライブラリは React と SheetJS(xlsx)のみです。

```
src/
  domain/      データ構造とデータ操作(UIに依存しない純粋関数)
    types.ts       型定義・形式バージョン(SCHEMA_VERSION)
    migrate.ts     旧形式からの移行と値の検証
    operations.ts  追加・更新・削除・集計
    merge.ts       読み込み時の統合(更新日時が新しい方を採用)
    dates.ts       日付(週は月曜始まり)
  store/       状態管理と localStorage 保存
  io/          Excel・JSON の入出力
  ui/          画面とコンポーネント
tests/         単体テスト
```

### 項目追加・形式変更のしかた

1. `src/domain/types.ts` に項目を追加し、`SCHEMA_VERSION` を 1 つ上げる
2. `src/domain/migrate.ts` の `MIGRATIONS` に「旧バージョン → 新バージョン」の変換を追加し、`sanitize*` 関数に既定値を足す
3. Excel に出す場合は `src/io/excel.ts` の `COLUMNS` に列を追加する

保存済みデータ・旧形式の Excel/JSON は、起動時・読み込み時に自動で新形式へ移行されます。新しい形式のファイルを古いアプリで読み込もうとした場合はエラーになります。

将来「差分を一覧で選んで取り込む画面」を作る場合は、`src/domain/merge.ts` の `diffData()`(レコードごとの判定)を利用できます。

## 4. デプロイ(無料の静的ホスティング)

ビルド結果(`dist/`)は相対パスで出力されるので、どのURLパスに置いても動きます。

### GitHub Pages(推奨)

GitHub Actions のワークフロー(`.github/workflows/deploy.yml`)を同梱しています。

1. GitHub で新しいリポジトリを作成する(社内データは含まれないので公開・非公開どちらでも可。非公開リポジトリで Pages を使うには有料プランが必要)
2. このフォルダを push する
   ```bash
   git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
   git push -u origin main
   ```
3. GitHub のリポジトリ画面 → **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする
4. **Actions** タブでワークフローが成功すると、`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます
5. 以降は `main` に push するたびに自動でテスト → ビルド → 公開されます

### Cloudflare Pages

1. Cloudflare ダッシュボード → **Workers & Pages → 作成 → Pages → Git に接続** で上記の GitHub リポジトリを選ぶ
2. ビルド設定
   - フレームワーク プリセット:`Vite`(または なし)
   - ビルド コマンド:`npm run build`
   - ビルド出力ディレクトリ:`dist`
   - 環境変数:`NODE_VERSION` = `22`
3. 「保存してデプロイ」で `https://<プロジェクト名>.pages.dev` に公開されます

※ Git 連携を使わない場合は `npm run build` 後、Cloudflare の「直接アップロード」で `dist` フォルダをアップロードしても公開できます。

### 注意

- データは「URL(ドメイン)ごと」にブラウザへ保存されます。公開URLを変更すると、以前のURLで入力したデータは新しいURLからは見えません。URLを変える前に Excel/JSON で書き出してください
- 検索エンジンに載らないよう `noindex` を設定していますが、URL を知っている人は誰でもアプリ自体は開けます(データは各自のブラウザ内にしかないので、他人に見られることはありません)
